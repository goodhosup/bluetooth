이 섹션은 규격을 "읽는" 단계에서 제품을 "만들고 고치는" 단계로 넘어갑니다. 어떤 호스트 스택을 고를지, Host와 Controller 사이에 무엇이 오가는지, 문제가 생겼을 때 로그와 스니퍼로 무엇을 봐야 하는지, 배터리를 얼마나 쓰는지, 그리고 출시 전에 거쳐야 하는 RF 시험과 SIG 인증까지 펌웨어·플랫폼 개발자가 실제로 부딪히는 주제를 모았습니다.

| 페이지 | 핵심 질문 |
|---|---|
| **호스트 스택 비교** | BlueZ, Zephyr, NimBLE, Android, Core Bluetooth, 칩 벤더 SDK는 무엇이 다르고, 무엇을 기준으로 고르나? |
| **HCI 명령과 이벤트** | Host와 Controller는 어떤 패킷을 주고받고, Opcode·오류 코드는 어떻게 읽나? |
| **로그 분석 (btmon·btsnoop·Wireshark)** | 연결 실패·0x3E·페어링 실패를 로그에서 어떻게 찾아내나? |
| **무선 스니퍼** | 공중의 패킷을 직접 잡으려면 무엇이 필요하고, 어디까지 볼 수 있나? |
| **저전력 설계와 전류 프로파일** | 광고·연결 이벤트 한 번에 전하를 얼마나 쓰고, 코인셀로 몇 년 가나? |
| **RF 시험과 안테나** | DTM으로 무엇을 재고, 안테나 매칭이 틀어지면 무슨 일이 생기나? |
| **인증 (Qualification)** | Bluetooth 로고를 쓰려면 어떤 절차와 번호(DN·QDID)가 필요한가? |

[[TIP("🟢 문제를 쫓는 순서 미리 보기")]]
필드에서 "연결이 끊겨요"라는 보고가 오면 대개 다음 순서로 범위를 좁힙니다.

1. **HCI 로그**(btmon·btsnoop)로 Host가 무엇을 요청했고 Controller가 어떤 상태·이유 코드로 답했는지 확인합니다.
2. 로그만으로 안 보이면 **스니퍼**로 공중의 LL 패킷(재전송, 빈 패킷, 채널 맵)을 봅니다.
3. 특정 기기·장소에서만 생기면 **RF**(출력, 감도, 안테나 디튜닝)와 공존 환경을 의심합니다.
4. 배터리 불만이라면 **전류 프로파일**로 이벤트당 전하와 수면 전류를 나눠 봅니다.
