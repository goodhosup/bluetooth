이 섹션은 Bluetooth Low Energy(LE)의 **컨트롤러** 쪽, 즉 무선(물리계층)과 링크 계층(Link Layer)을 다룹니다. 호스트(L2CAP·ATT·GATT·GAP)가 "무엇을 보낼지"를 정한다면, 컨트롤러는 "언제, 어느 채널에서, 어떤 모양의 패킷으로" 보낼지를 정합니다. 페이지는 물리계층 → 링크 계층 → 고급 기능 순서로 읽으면 자연스럽습니다.

### 물리계층

| 페이지 | 핵심 질문 |
|---|---|
| **LE PHY (1M·2M·Coded)** | 1M·2M·Coded PHY는 무엇이 다르고, 거리와 속도는 어떻게 맞바꾸나? |
| **채널과 송신 전력** | 40개 채널은 어떻게 나뉘고, 광고 채널은 왜 2402·2426·2480 MHz인가? |
| **패킷 구조** | 프리앰블부터 CRC까지 한 패킷에는 무엇이 들어 있고, 공중 시간은 얼마인가? |

### 링크 계층

| 페이지 | 핵심 질문 |
|---|---|
| **링크 계층 상태 기계** | 링크 계층은 어떤 상태를 오가며, 여러 역할을 동시에 할 수 있나? |
| **레거시 광고** | 4.0 방식 광고 PDU 7종은 어떻게 쓰이고, 31바이트 한계는 왜 생겼나? |
| **확장 광고** | 5.0 확장 광고는 어떻게 주 채널을 비우고 1650바이트까지 실어 나르나? |
| **주기적 광고와 PAwR** | 연결 없이 정해진 시각에 데이터를 받으려면? 응답까지 받으려면(PAwR)? |
| **스캔과 필터** | 스캐너는 얼마나 자주 들어야 하고, 쓸데없는 보고는 어떻게 거르나? |
| **연결 수립** | `CONNECT_IND` 한 번으로 연결 파라미터가 어떻게 정해지나? |
| **연결 이벤트와 파라미터** | 연결 간격·지연·감시 타임아웃은 전력과 지연을 어떻게 바꾸나? |
| **채널 선택 알고리즘** | CSA #1과 #2는 어떻게 다음 채널을 고르나? |
| **LL 제어 절차** | 연결 중 파라미터·PHY·암호화는 어떤 절차로 바뀌나? |
| **데이터 길이 확장 (DLE)** | 27바이트 PDU를 251바이트로 늘리면 처리량이 얼마나 오르나? |
| **LE 전력 제어** | 상대에게 송신 전력을 올리거나 내려 달라고 어떻게 요청하나? |

### 고급 기능

| 페이지 | 핵심 질문 |
|---|---|
| **등시성 채널 (CIS·BIS)** | LE Audio는 정해진 시각에 오디오 프레임을 어떻게 보장하나? |
| **방향 탐지 (AoA·AoD)** | CTE와 안테나 배열로 각도를 어떻게 재나? |
| **Channel Sounding** | 6.0의 위상·왕복 시간 측정으로 거리를 어떻게 cm 단위로 재나? |

[[TIP("🟢 Classic과 다른 점 미리 보기")]]
같은 2.4 GHz 대역을 쓰지만 LE는 처음부터 "가끔 깨어나 짧게 말하기"를 목표로 설계되었습니다.

1. **채널이 적고 넓습니다** — 1 MHz 79개 대신 2 MHz 40개. 그중 3개(37/38/39)를 광고 전용으로 떼어 두어 기기 발견이 빠릅니다.
2. **연결 없이도 통신합니다** — 광고·주기적 광고·BIS처럼 연결 없는 전송이 1급 기능입니다.
3. **슬롯이 아니라 이벤트 단위입니다** — 625 µs 슬롯 대신, 광고 이벤트·연결 이벤트가 시작되면 T_IFS 150 µs 간격으로 패킷을 주고받고 다시 잠듭니다.
4. **PHY를 고를 수 있습니다** — 5.0부터 속도(2M)와 거리(Coded) 중 하나를 링크마다 선택합니다.
