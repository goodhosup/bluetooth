Bluetooth Mesh는 수십에서 수천 개의 LE 기기를 하나의 **다대다(many-to-many)** 네트워크로 묶는 규격입니다. 조명·센서·스위치처럼 건물 전체에 흩어진 기기가 서로 메시지를 전달해 주므로, 휴대폰이나 허브가 모든 기기와 직접 연결될 필요가 없습니다. 이 섹션은 Mesh의 동작 원리부터 1.1에서 추가된 기능까지 순서대로 다룹니다.

| 페이지 | 핵심 질문 |
|---|---|
| **Mesh 개요와 관리형 플러딩** | 라우팅 테이블 없이 메시지가 어떻게 건물 끝까지 가나? Relay·Proxy·Friend·Low Power 노드는 무엇이 다른가? |
| **프로비저닝** | 새 전구가 네트워크에 들어올 때 무엇을 받고, 어떻게 인증하나? PB-ADV와 PB-GATT의 차이는? |
| **네트워크·전송·접근 계층** | 네트워크 PDU에는 어떤 필드가 있나? 긴 메시지는 어떻게 쪼개고 다시 모으나? |
| **모델** | "불을 켜라"는 명령은 어떤 모델·opcode로 표현되나? 요소(element)는 왜 필요한가? |
| **Mesh 보안** | NetKey·AppKey·DevKey는 각각 무엇을 지키나? IV Index와 키 갱신은 왜 필요한가? |
| **Mesh 1.1** | Mesh Profile 1.0에서 Mesh Protocol 1.1로 바뀌며 무엇이 추가되었나? |

[[TIP("🟢 Mesh는 LE 위에서 어떻게 동작하나")]]
Mesh는 새 무선 방식이 아니라 **LE 컨트롤러를 그대로 쓰는 호스트 쪽 규격**입니다. Core 4.0 이상의 LE 칩이면 원칙적으로 소프트웨어만으로 Mesh 노드가 될 수 있습니다.

1. **광고 베어러(ADV bearer)** — 메시지를 LE **광고 패킷**(AD Type `Mesh Message`)에 실어 광고 채널 37/38/39로 뿌리고, 노드는 계속 스캔해서 받습니다. 연결이 없으므로 누구에게나 동시에 전달됩니다.
2. **GATT 베어러** — 스캔을 오래 할 수 없는 휴대폰은 **Proxy 노드**와 일반 LE 연결을 맺고 GATT(Mesh Proxy Service)로 메시지를 주고받습니다.
3. **보안은 Mesh 자체 계층에서** — LE 페어링이나 링크 계층 암호화를 쓰지 않고, 모든 메시지를 NetKey(네트워크 계층)와 AppKey(상위 전송 계층)로 두 번 보호합니다.
4. **응용은 모델로** — "켜기/끄기", "밝기", "센서 값" 같은 동작은 **모델**이라는 표준 메시지 묶음으로 정의되어, 제조사가 달라도 서로 제어할 수 있습니다.

따라서 LE 섹션의 **레거시 광고**와 **스캔**, LE 호스트 섹션의 **GATT**를 먼저 읽어 두면 이 섹션이 쉽게 읽힙니다.
