# LE PHY (1M·2M·Coded)

!!! spec "규격 · 버전"
    Core v6.0 Vol 6 Part A (Physical Layer) · Vol 6 Part B §3 (비트 스트림 처리: 부호화, Coded PHY 패턴 매퍼)
    Core 4.0 LE 1M 도입 → 5.0 LE 2M·LE Coded(S=2/S=8) 추가 → 5.4 광고에서 S 값 선택(Advertising Coding Selection) → 6.0 Channel Sounding 전용 2M 2BT PHY

!!! basic "한눈에 보기"
    LE의 물리계층은 모두 같은 **GFSK**(가우스 주파수 편이 변조) 신호를 씁니다. 다른 것은 "얼마나 빨리 말하느냐"와 "같은 말을 몇 번 되풀이하느냐"입니다.

    1. **LE 1M** — 초당 100만 심볼, 1심볼 = 1비트. 4.0부터 있는 기본형이며 모든 LE 기기가 지원합니다.
    2. **LE 2M** — 초당 200만 심볼. 같은 데이터를 절반 시간에 보내 전력을 아끼지만 거리는 약간 줄어듭니다.
    3. **LE Coded** — 1M 신호 위에 오류 정정 부호를 얹고 비트를 2배(S=2) 또는 8배(S=8)로 늘려 보냅니다. 느리지만 멀리 갑니다.

    비유하자면 2M은 "빨리 말하기", Coded는 "천천히, 또박또박 되풀이해 말하기"입니다.

## 세 PHY 비교 { .l2 }

| 항목 | LE 1M | LE 2M | LE Coded S=2 | LE Coded S=8 |
|---|---|---|---|---|
| 도입 | 4.0 | 5.0 | 5.0 | 5.0 |
| 심볼율 | 1 Msym/s | 2 Msym/s | 1 Msym/s | 1 Msym/s |
| 데이터율 | 1 Mbps | 2 Mbps | 500 kbps | 125 kbps |
| 변조 | GFSK, BT = 0.5 | GFSK, BT = 0.5 | GFSK, BT = 0.5 | GFSK, BT = 0.5 |
| 변조 지수 | 0.45–0.55 (안정 지수 옵션 0.495–0.505) | 같음 | 같음 | 같음 |
| 프리앰블 | 8비트 (8 µs) | 16비트 (8 µs) | 80 µs (부호화 안 함) | 80 µs |
| FEC | 없음 | 없음 | 컨볼루션 부호 R = 1/2 | 컨볼루션 부호 + 패턴 매퍼 ×4 |
| 수신 감도 요구 | −70 dBm | −70 dBm | −75 dBm | −82 dBm |
| 지원 의무 | 필수 | 선택 | 선택 | 선택 |

2M PHY는 주파수 편이가 1M의 두 배여서 신호가 2 MHz 채널 폭을 거의 꽉 채웁니다. 그래서 인접 채널 간섭 요구가 1M과 다르고, 광고 주 채널(37/38/39)에서는 쓸 수 없습니다. 광고 주 채널에는 1M과 Coded만 쓰고, 2M은 [확장 광고](extended-advertising.md)의 보조 채널과 연결에서 씁니다.

## Coded PHY의 부호화 { .l2 }

Coded 패킷은 두 개의 **FEC 블록**으로 나뉩니다.

| 구간 | 내용 | 부호화 | 길이 |
|---|---|---|---|
| 프리앰블 | `00111100` 패턴 10회 반복 | 없음 | 80 µs |
| FEC 블록 1 | Access Address (32비트) | 항상 S=8 | 256 µs |
| | **CI**(Coding Indicator, 2비트) — 블록 2의 S 값 | 항상 S=8 | 16 µs |
| | **TERM1**(3비트 0) | 항상 S=8 | 24 µs |
| FEC 블록 2 | PDU + CRC | S=2 또는 S=8 | (PDU + 3 B) × 8 × S µs |
| | **TERM2**(3비트 0) | 블록 2와 같음 | 3 × S µs |

부호화 과정은 두 단계입니다.

1. **컨볼루션 부호기** — 구속장 K = 4, 부호율 1/2의 비재귀 부호입니다. 입력 1비트마다 두 생성 다항식 \(G_0 = 1 + D + D^2 + D^3\), \(G_1 = 1 + D^2 + D^3\)의 출력 2비트를 냅니다. TERM 필드의 3비트 0은 부호기의 레지스터(K − 1 = 3개)를 0으로 비워, 수신기의 비터비 복호가 각 블록 끝에서 상태를 확정하게 합니다.
2. **패턴 매퍼** — S=2에서는 부호기 출력을 그대로 보냅니다(P = 1). S=8에서는 각 비트를 4심볼로 바꿉니다(0 → `0011`, 1 → `1100`, P = 4). 그래서 S=8은 정보 1비트가 8심볼이 됩니다.

수신기는 FEC 블록 1을 늘 S=8로 복호해 CI를 읽은 뒤, 블록 2를 어떤 S로 복호할지 결정합니다. Access Address를 S=8로 보내므로 Coded의 패킷 검출 자체가 1M보다 훨씬 강합니다.

## 공중 시간 (airtime) { .l2 }

아래 값은 PDU 헤더 2 B와 CRC 3 B를 포함한 패킷 하나의 길이입니다(`tools/bt_numbers.py` 출력, 단위 µs). MIC는 암호화된 연결에서 붙는 4 B입니다.

| PHY | 빈 PDU | 27 B | 27 B + MIC | 251 B | 251 B + MIC |
|---|---|---|---|---|---|
| 1M | 80 | 296 | 328 | 2088 | 2120 |
| 2M | 44 | 152 | 168 | 1048 | 1064 |
| Coded S=2 | 462 | 894 | 958 | 4478 | 4542 |
| Coded S=8 | 720 | 2448 | 2704 | 16784 | 17040 |

연결 이벤트를 251 B 패킷으로 꽉 채웠을 때 ATT Notification 기준 응용 처리량 상한은 1M ≈ 791 kbps, 2M ≈ 1402 kbps, S=2 ≈ 372.5 kbps, S=8 ≈ 109.6 kbps입니다. 계산 가정은 [데이터 길이 확장 (DLE)](data-length.md)과 [처리량 최적화](../host/throughput.md)에서 다룹니다.

## 도달 거리와 PHY 선택 { .l2 }

수신 감도 요구치 차이를 링크 버짓 이득으로 보고, 경로 손실 지수 \(n\)에서 거리 비는 \(10^{\Delta/(10n)}\)로 계산할 수 있습니다(같은 송신 출력, 같은 안테나 가정).

| PHY | 1M 대비 감도 이득 \(\Delta\) | 자유 공간 (\(n = 2\)) | 실내 (\(n = 3\)) |
|---|---|---|---|
| 1M | 0 dB | 1.0× | 1.0× |
| 2M | 0 dB (요구치 기준) | 1.0× | 1.0× |
| Coded S=2 | 5 dB | 10^(5/20) ≈ 1.8× | 10^(5/30) ≈ 1.5× |
| Coded S=8 | 12 dB | 10^(12/20) ≈ 4.0× | 10^(12/30) ≈ 2.5× |

"Coded PHY로 거리 4배"라는 홍보 문구는 자유 공간에서 12 dB 이득을 환산한 값입니다. 실제 칩의 감도는 요구치보다 훨씬 좋고, 2M은 잡음 대역폭이 넓어 같은 칩의 1M보다 대략 3 dB 안팎 나쁩니다. 실내에서는 벽·사람에 의한 감쇠 때문에 이득이 더 작게 나타납니다. 링크 버짓 계산은 [무선 전파와 링크 버짓](../basics/radio-channel.md)을 참고하세요.

| 상황 | 권장 PHY | 이유 |
|---|---|---|
| 대용량 전송(펌웨어 업데이트, 로그) | 2M | 같은 데이터를 절반 시간에 → 전류·충돌 확률 감소 |
| 일반 센서·웨어러블 | 1M 또는 2M | 호환성(1M은 필수), 적당한 거리 |
| 건물 밖·창고·스마트 미터 | Coded S=8 | 감도 이득 최대, 대신 패킷이 8배 이상 길어짐 |
| 거리와 속도의 절충 | Coded S=2 | 5 dB 이득, 처리량은 S=8의 3배 이상 |
| LE Audio (CIS/BIS) | 2M | 공중 시간을 줄여 등시성 일정에 여유 확보 |

??? expert "전문가 노트 — PHY 갱신, 비대칭 PHY, Coded의 함정"
    **연결 중 PHY 변경.** 연결은 항상 광고를 받은 PHY(1M 또는 Coded)로 시작하고, 이후 `LL_PHY_REQ`/`LL_PHY_RSP`/`LL_PHY_UPDATE_IND` 절차로 바꿉니다. 호스트는 `HCI_LE_Set_Default_PHY`, `HCI_LE_Set_PHY`로 선호를 알리고, 결과는 `HCI_LE_PHY_Update_Complete` 이벤트로 받습니다. 송신·수신 방향을 따로 정할 수 있어 TX는 2M, RX는 1M 같은 **비대칭 PHY**도 가능합니다. → [LL 제어 절차](ll-control.md)

    **Coded의 S 값은 누가 정하나.** 연결에서는 `HCI_LE_Set_PHY`의 `PHY_Options`로 S=2/S=8 선호를 줄 수 있지만 최종 선택은 송신 측 컨트롤러입니다. 수신 측은 매 패킷의 CI로 알아냅니다. 광고에서는 5.4 이전까지 호스트가 S를 지정할 수 없었고, 5.4의 Advertising Coding Selection이 `HCI_LE_Set_Extended_Advertising_Parameters` V2에 주·보조 광고 PHY 옵션(선호/필수 S=2·S=8)을 추가했습니다.

    **긴 패킷의 대가.** S=8에서 251 B 패킷 하나는 17 ms가 넘습니다. 연결 간격이 짧으면 한 이벤트에 패킷 하나도 다 못 넣고, 클럭 오차(SCA) 누적과 채널 간섭에 노출되는 시간도 길어집니다. Coded PHY에서는 DLE의 최대 시간(`connMaxTxTime` 등)이 바이트 수보다 먼저 한계가 됩니다.

    **안정 변조 지수.** 변조 지수를 0.495–0.505로 좁게 지키는 송신기는 이를 기능 비트로 알릴 수 있고, 수신기는 이 정보를 써서 감도를 조금 더 끌어낼 수 있습니다. 방향 탐지의 CTE 품질에도 유리합니다.

## Classic ↔ LE 비교

| 항목 | Classic (BR/EDR) | LE |
|---|---|---|
| 변조 | GFSK (BR), π/4-DQPSK·8DPSK (EDR) | GFSK만 |
| 심볼율 | 1 Msym/s | 1 또는 2 Msym/s |
| 최고 데이터율 | 3 Mbps (EDR) | 2 Mbps (2M) |
| 장거리 모드 | 없음 | Coded PHY (125/500 kbps) |
| 변조 지수 | 0.28–0.35 | 0.45–0.55 |
| FEC | 패킷 종류별 1/3 반복·2/3 해밍 (DM 패킷 등) | Coded PHY의 컨볼루션 부호 |
